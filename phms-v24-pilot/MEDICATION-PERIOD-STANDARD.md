# v2.4.37 — start-first end-date constraint

Keep treatment period order: start, duration and unit, end. End date is disabled until a valid start date is entered, with Thai prompt. Native min equals start; state also rejects any attempted earlier end, preserving the prior valid value. Same-day end allowed (one inclusive day). When changing start in manual-end mode invalidates the end, clear end and derived duration; when duration is authoritative, retain duration and recalculate end. Clearing start removes computed end while retaining entered duration. Final validation catches legacy invalid ranges and end without start. Native picker visual restrictions depend on browser; state enforces the rule. No change to treatment calculations, supply estimates, or authentication.

# PHMS Medication period calculation v2.4.27

Optional start, inclusive end and whole calendar-day duration. Start + duration calculates end = start + duration - 1. Start + end calculates duration = end - start + 1. Last edited duration or end determines which is authoritative when start changes. Clearing end or duration removes the paired derived value. Duration without start is allowed while editing but must have start before review/save. Reject fractional/nonpositive durations, reversed dates and unsupported overflow. Keep ISO date-only strings, Thai Buddhist date display. Date differences use UTC date arithmetic, not local elapsed hours. Calendar days are not dose count, especially intermittent/PRN schedules. No implied prescription, automatic discontinuation, or production changes. Continuous medication can leave end and duration blank.
