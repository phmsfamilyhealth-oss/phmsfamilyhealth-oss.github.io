# PHMS — Delete Action Standard v1.0

Status: **UI baseline** · 10 November 2026
Scope: ทุกหน้าที่ผู้ใช้สามารถลบรายการใน PHMS (LIFF, เว็บฟอร์ม, หน้าภาพรวม และ LINE Flex Message ที่รองรับการกระทำนี้)
Initial implementation: `phms-v24-pilot/prototype/index.html`

## 1. วัตถุประสงค์
ใช้มาตรฐานการมองเห็นและความหมายแบบเดียวกันสำหรับคำสั่ง “ลบ” ทุกหมวด ลดภาระการเรียนรู้ของผู้สูงอายุ แต่ **ไม่** เปลี่ยน authorization, retention, auditing, soft-delete, หรือ backend contract เดิม

## 2. อัตลักษณ์ปุ่มลบ (Single PHMS Delete Visual Contract)

- ข้อความหน้าปุ่ม: **ลบ** พร้อมไอคอนรูปถังขยะ **ชนิดเส้น (SVG)** ไม่ใช้ Emoji เพียงอย่างเดียว และไม่ใช้ปุ่มสีแดงทึบขนาดใหญ่
- หน้าปุ่ม: พื้น `#FFF2F3`, เส้นขอบ `#B77A85`, ตัวอักษรและไอคอน `#8C3146`
- ขนาดที่มองเห็น: กว้าง **66 px**, สูง **32 px**, ขอบมน 9 px
- พื้นที่กดจริง: อย่างน้อย **44 × 44 px**; บนอุปกรณ์จอแคบให้ปรับความกว้างที่มองเห็นเป็น 60 px โดยไม่ลดความสูงพื้นที่กด
- ข้อความ “ลบ” ต้องไม่ถูกตัด; `aria-label` ระบุรายการเฉพาะ เช่น “ลบรูปใบนัด 1”
- กลางแนวตั้งของรายการเสมอ ทั้งรายการ 1 และ 2+ บรรทัด
- ปุ่มทางเลือกเช่น “ดูรูป” ใช้สีน้ำตาล/ครีม และต้องแยก visual hierarchy ชัดเจนจากปุ่มลบ
- คงลำดับรายการ ความยาวข้อความ และความสามารถในการใช้แป้นพิมพ์/VoiceOver

## 3. กฎปฏิสัมพันธ์ — แยกตามประเภทข้อมูล

| ประเภท | การกดลบ | การยืนยัน | หมายเหตุ |
|---|---|---|---|
| รายการร่างที่ยังไม่ได้บันทึก (Checklist) | หายทันที | ไม่ต้อง | ไม่แสดง Undo/Toast; ผู้ใช้เพิ่มใหม่ได้ |
| รูปใบนัดที่เพิ่งเลือกในร่าง | เอารูปออกจากรายการทันที | ไม่ต้อง | คืนหน่วยความจำ `ObjectURL` และอัปเดตจำนวนรูป |
| รายการตรวจ/หัตถการในร่าง | เอาออกทันที | ไม่ต้อง | คงสถานะบันทึกจริง/คำเตือนเดิม |
| ข้อมูลที่บันทึกจริง เช่น นัด ยา เอกสาร และสมาชิกครอบครัว | ตาม workflow เดิม | ยืนยันตามระดับความเสี่ยงของรายการ | **ห้าม** ใช้กฎลบทันทีแทนการตรวจสิทธิ์/บันทึกประวัติ/rollback |
| กรณีไม่มีสิทธิ์ | ไม่แสดงหรือปิดการใช้งานตามกฎสิทธิ์ส่วนกลาง | ไม่เกี่ยวข้อง | ห้ามเพิ่มช่องทาง bypass ฝั่ง Client |

## 4. จุดเริ่มต้นที่ปรับแล้ว

ในหน้า Smart Appointment Pilot ใช้ `makePhmsDeleteButton(ariaLabel, onDelete)` + `.phms-delete-button` / `.phms-delete-face` ร่วมกันทั้งสามตำแหน่ง:

1. สิ่งที่ต้องนำไป / Checklist
2. รูปใบนัดที่แนบในแบบฟอร์ม
3. รายการตรวจและหัตถการที่ใส่เพิ่มเติม

ส่วนของรูปใช้การ์ดแนวนอนแบบหนึ่งรูปต่อแถว (ภาพตัวอย่าง + ชื่อไฟล์ + ปุ่ม “ดูรูป” และ “ลบ” แยกสี) และรองรับจอ iPhone ขนาดเล็ก

## 5. การนำไปใช้กับช่องทางอื่น

- **หน้าเว็บ/LIFF**: ใช้คอมโพเนนต์และโทเคนเดียวกัน ห้ามสร้าง CSS แบบลบแยกเองหรือใช้ Emoji เดี่ยว ๆ
- **LINE Flex Message**: ไม่รองรับ CSS/SVG ฝังแบบเว็บโดยตรง ให้ใช้รูปแบบปุ่มสื่อความหมายเดียวกันเท่าที่โครงสร้าง Flex อนุญาต (คำว่า “ลบ” สีแดงเข้มบนพื้นชมพูอ่อน) และคง server-side authorization
- **ข้อมูลย้อนหลังและ Production**: ต้องตรวจ HEAD/Deployment/Role Permissions และทดสอบปุ่มในช่องทางนั้นจริงก่อนเปลี่ยน ห้ามถือว่าการเพิ่มโทเคนใน LIFF ทำให้ LINE Flex หรือแอปที่ deploy แยกกันเปลี่ยนอัตโนมัติ

## 6. Acceptance / Regression

- 3 ปุ่มลบของหน้าฟอร์มนัดหมายใช้ helper เดียวและมีสี ขนาด ไอคอน คำอธิบาย และพื้นที่สัมผัสเท่ากัน
- กดลบในร่างไม่ขึ้น `Cancel / OK`, ปุ่ม “เลิกทำ” หรือป้ายยืนยันซ้ำ
- เลือก/ลบรูปจริงแล้วจำนวนและ thumbnail เปลี่ยนถูกต้อง; “ดูรูป” ไม่ลบรูป
- Checklist ที่มี 1 บรรทัดไม่สูงเท่ารายการที่มี 2 บรรทัดโดยไม่จำเป็น
- ระบบไม่แก้ API, RLS, การตรวจสิทธิ์ หรือการลบข้อมูล Production
- GitHub Pages deploy ผ่าน และต้องทดสอบ LINE iPhone ภายหลัง deploy ก่อนถือว่าใช้งานจริงผ่าน

**หมายเหตุ:** เอกสารนี้เป็นกฎกลางของ PHMS แต่การปรับทุกจุดใน LINE webhook/backend และ Production UI ที่อยู่นอก Smart Appointment Pilot ต้องตรวจและ deploy แยกตามโมดูล ห้ามสรุปว่า rollout ครอบคลุมแล้วจากการ commit ฟอร์มเพียงหน้าเดียว
